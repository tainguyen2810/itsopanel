# G4: Backup/Restore

- **Trạng thái:** `pending_vm` — chưa chạy trên VM (2026-11-23, `v1.0.0-rc.1`). `v1.0.0` chỉ khi G1–G8 đều `pass` (D-15, D-47, ADR 0060).
- **Tiêu chí (ROADMAP §Production Gate):** Restore ngẫu nhiên 10 account, có ít nhất 1 lần sang server khác. Panel không xóa được backup immutable.

## Tiêu chí đo được

1. Backup files → xóa site → restore → sha256 từng file khớp + HTTP 200 (B1)
2. DB: backup → xóa dòng → restore → số dòng + CHECKSUM TABLE khớp (B2)
3. rest-server `--append-only`: `backup.forget` bằng credential panel thất bại (B3)
4. 10 account chọn ngẫu nhiên khôi phục thành công, 1 lượt sang server khác

## Đã kiểm tự động trong container (CI)

- Pest `tests/Feature/Phase8/BackupTest.php` (7 test), restore qua agent giả, khóa snapshot
- Go `TestBackupRestoreSymlinkAtTarget`

Lệnh và kết quả thật: `TEST_REPORT.md` (Phase 12), báo cáo `docs/reports/phase-12.md`.

## Phần VM

`sudo bash tests/vm/gate.sh --release A --only G4 --g4-report <file>`; file ghi `restores=10`, `cross_server=PASS` và bảng 10 lượt (account, snapshot, sha256 khớp, HTTP).

Không có báo cáo 10 lượt → `partial`.

Sau khi chạy: dán bảng của `/root/itso-vm-gate.md` vào mục **Bằng chứng** dưới đây, ghi ngày/phiên bản/cấu hình VM, rồi
`--record` (hoặc `php artisan itso:gate-record G4 <pass|fail|partial>`) để trang **Sẵn sàng production** hiển thị.
