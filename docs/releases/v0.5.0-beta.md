### Mới ở Phase 11

- **Số liệu:** server (CPU, RAM, swap, disk, inode, IO, network, load, dịch vụ) mỗi phút, account từ cgroup (`itso-acct-<uid>.slice`: CPU, RAM, IO, tasks) mỗi 5 phút; giữ 7 ngày (partition theo ngày) + rollup 1 giờ 90 ngày; biểu đồ 1 giờ → 90 ngày; top account theo tài nguyên.
- **Cảnh báo:** rule `metric op ngưỡng` kéo dài N giây, phạm vi server/account/website, mức info → critical; `pending → firing → resolved` (hysteresis 2 lượt), nhắc lại 4 giờ, ack, silence 1h/4h/24h, xem trước "đang khớp N đối tượng". 9 rule mặc định (mất kết nối, disk, inode, RAM, dịch vụ lõi, uptime, chứng chỉ, backup, quota; sửa được, không xóa được). **Server mất kết nối → cảnh báo ≤ 2 phút.**
- **Uptime:** kiểm HTTP(S) website do panel quản lý từ server chứa website (op `uptime.probe`), down sau 3 lần lỗi, % uptime 24h/7d/30d, hạn chứng chỉ; USER bật/tắt cho site của mình.
- **Thông báo:** in-app + email (SMTP ở Cài đặt) + Telegram + webhook ký HMAC; chặn SSRF (DNS → IP → ghim, chặn loopback/metadata/link-local, dải riêng chỉ khi bật, không redirect, 5 giây, 64 KB); queue `notifications`, thử lại 1/5/15 phút, nhật ký gửi + gửi lại, giới hạn 30 tin/phút/kênh (gộp tin tóm tắt); tùy chọn theo người × sự kiện × kênh. USER nhận quota 80/100 %, chứng chỉ sắp hết hạn/gia hạn lỗi, backup lỗi, account bị khóa/mở, website down/up, WordPress rollback.
- **Realtime nhẹ:** tiến độ job qua SSE (Redis pub/sub, `Last-Event-ID`, heartbeat, poll dự phòng); dashboard có số cảnh báo đang bật và sự kiện bảo mật 24 giờ thật.

## Thay đổi cần chú ý

- **Phiên bản:** `0.5.0-beta` (agent/CLI, `config/itso.php`, `make release`).
- **Migration Phase 9–11:** thêm bảng node/relay/transfer (9), Docker/WordPress/Software (10), `metric_samples` (partition), `metric_rollups`, `alert_rules`, `alerts`, `uptime_checks`, `uptime_results`, `notification_channels`, `notification_deliveries`, `notification_preferences` (11). `artisan migrate` chạy khi cài/cập nhật.
- **Worker phải nghe queue `notifications`** (`itso-worker@` đã đổi sang `--queue=default,notifications`). Cập nhật bằng gói mới thì unit được thay; tự cài thì sửa tay.
- **Scheduler** chạy thêm `metrics-rollup`, `metrics-prune`, `alerts-evaluate`, `uptime-probe`, `notifications-tick`, `certificates-expiry`.
- USER không còn nhận thông báo cảnh báo rule (`alert.*`); thay bằng sự kiện nghiệp vụ (vd. `website.down`).
- Webhook không đi qua proxy HTTP của môi trường (để giữ ghim IP chống SSRF).

## Giới hạn đã biết

1. **Chờ VM:** Phase 4–11 (`make test-vm`, `tests/vm/phase5.sh` → `phase11.sh`): cài sạch ≤ 10 phút, enforcement, HTTPS thật, safe-apply tường lửa, DR 2 VM, multi-server 2 VM, Docker/WordPress thật, cgroup v2 + nftables + SMTP thật (Phase 11: M0–M5).
2. **Gửi thật ra Internet** (SMTP ngoài, Telegram) chưa thử từ container; chờ người dùng cấu hình trên VM (M4).
3. Uptime kiểm từ một điểm (chính server chứa site); kiểm nhiều điểm: DEFERRED.
4. Log container realtime: DEFERRED (hiện tail). Basic auth cho staging WordPress chưa có.
5. Tiêu chí hiệu năng chưa đo: 200 account/server (`metric_samples`), khôi phục 1 site 5 GB ≤ 15 phút — Phase 12.
6. Gửi email qua SMTP không đi qua SsrfGuard (chỉ SUPER_ADMIN cấu hình, có audit).
7. `shellcheck`, `staticcheck`, coverage % không có trên container CI hiện tại.
